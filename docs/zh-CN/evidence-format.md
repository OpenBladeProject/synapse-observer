# 证据格式

[English](../evidence-format.md) | 简体中文 | [Русский](../ru-RU/evidence-format.md)

每次显式导出都包含 `manifest.json`、`coverage-draft.json`、`annotation-draft.json`、`quality-receipt.json` 和 `README.txt`。清单记录采集器构建/源码修订、清单各节、操作标记、feature 和特殊按键观测、引导覆盖情况及被拒记录数。其余 JSON 文件提供完整的 OpenBlade 覆盖检查表、有边界的操作窗口和明确的采集质量回执，不包含自动上传或命令重放指令。请参阅[证据 ZIP 的内容](capture-contents.md)。

<a id="inventory"></a>
## 清单

Windows 注册表身份包括制造商、产品、SKU、BIOS 版本和 BIOS 日期。HID 清单包括 Razer VID/PID、usage、版本和报告结构。相关 Synapse 进程/模块的来源信息包括文件名、版本和哈希。每个设备接口拥有会话内不透明标签。原始实例路径、进程 ID、命令行、用户名和序列号清单字段不会导出。

本地接口路径和 USB 祖先关系仅存在于内存中，用于附加观测时识别同一物理笔记本。即使笔记本位于集线器之后，也会保留最近的匹配物理 USB 父设备。键盘类 Raw Input 名称通过精确的 SetupAPI 设备实例身份与所选 HID 候选项关联；无法匹配或存在歧义的名称被排除。这些路径和身份不属于导出包 DTO。枚举不会借用已知机型的命令，描述符匹配也不授予写入许可。

<a id="observations"></a>
## 观测

一个操作具有由序列生成的 ID、精确选定的接口标签、API、进入和 API 返回时间、状态/错误元数据及载荷处理结果。输入调用记录与返回缓冲区记录相互独立。实际输出缓冲区容量独立于请求长度记录。尚未完成的原生 I/O 没有已完成响应。`HidD_GetFeature` 不返回实际字节数；`returnedLengthUnknown` 在其成功返回的缓冲区上保留此限制，而 `returnedBytes` 保持 null。此限制与采集丢失无关，不会使完整缓冲区被排除在已审核隐私语法之外。完整观测到的 API 失败保留失败状态和原生错误，单独于丢失或不完整观测计数。GET_FEATURE 既可返回设置确认，也可返回查询响应。注释角色和 getter 覆盖依据报告的命令身份，而非传输 API 名称。

仅经过审核的数值型散热、风扇、电池、性能、键盘行为、适配器功率，以及有边界的数值或 RGB 灯效封装，在通过命令专用边界、校验和、保留字节和填充检查后，才可导出其字节。灯效语法覆盖精确的 91 字节行、锁存、亮度、徽标和效果报告，以及审核过的 375 字节矩阵帧结构。识别一个值或帧是隐私判断，不证明机型的完整范围、布局或支持。已完成的 HID_GET_FEATURE IOCTL 响应可能包含不带报告 ID 的 90 字节包。它们需要匹配的 91 字节 feature 描述符、至少 91 的输出容量、无缺口的成功完成，以及同样完整的隐私语法检查。导出保留原始 90 字节，报告 ID 为 null。这是隐私投影，不是命令支持决定。未知命令正文仍以元数据保留，附有受限的头部提示和长度，不会仅因陌生就被丢弃。任意 feature 缓冲区可能含标识符，因此仅匹配到 Razer 句柄不足以允许导出载荷。

用户选择或输入的初始、更改和恢复值标记为 `userReported`。“Setting unavailable”（设置不可用）表示用户在 Synapse 中找不到该设置，不表示硬件缺少该能力。完成一张记录卡片表示引导用户序列结束，不代表固件验证完成。

可选的前台特殊按键探测持续五秒，仅保留狭窄提示按键策略允许的有限输入。预期按键和模式由用户报告。提示产生的事件归入通用输入证据叶项，除非观测到的 Windows 按键或已审核信号能独立识别该信号。普通键入和宏被省略；Fn+P 提示期间的 P 事件不证明 Fn 被按住，也不证明该键控制性能。探测结果与按键行为声明分开；没有输入信号绝不会替换先前报告，也不会将已声明按键标为不可用。

队列、报告正文、记录数、文本和清单总大小均有限制。被省略的载荷、被拒记录、队列丢失及未完成恢复仍明确可见。原生丢弃计数在每次记录开始时重置，但会话损失和已有证据持续累积。无论由轮询还是停止操作先发现，原生失败只计一个缺口。若设置更改期间轮询失败，采集器会请求在限定时间内停止自己的观测器，并保留精确初始设置的恢复提醒。成功清理不会抹去部分记录警告。即使没有操作窗口包含观测，观测器丢失标记也会出现在质量回执中。调用 ID 包含记录前缀，使连续记录中的请求/响应配对保持独立。ZIP 使用私有临时文件写入，最后原子重命名；关闭 GUI 会等待进行中的导出完成。导出先冻结会话，再将草稿准备和序列化移到 UI 线程之外。所有草稿共享同一组操作窗口。并发停止和关闭会加入同一次清理。普通停止和可恢复的格式错误记录拒绝期间，一个读取器保持活动，直到原生最终排空完成。致命读取器故障会停止该读取器；清理执行最终排空并报告损失。队列丢弃计数独立于记录解析检查，并再次从停止结果检查。如果首次停止等待未获确认，会再进行一次有界等待，保留读取器，在最终排空前捕获较晚的原生完成结果。第二次结果仍未确认时，仍视为部分记录失败。连续格式错误记录保留每条被拒记录的计数，但每次记录只产生一个丢失标记。

准确限制和隐私分类器见 `src/SynapseObserver.Core` 中的 `EvidenceLimits` 和 `FeaturePayloadPrivacy`。维护者应在推导机型专用命令前检查观测层和缺口。

数值范围不是本采集器的生产准入规则。在经过精确审核的散热、Custom CPU/GPU、固定风扇和充电上限命令族内，不熟悉的数值会保留，并标记 `numericMeaningUninterpreted: true`。报告族、控制标签、通道、长度、校验和、填充、来源和状态检查仍然适用。查询输入参数必须符合已审核的全零结构。这样可以研究新机型的数值，而不声称已经理解或支持它们。

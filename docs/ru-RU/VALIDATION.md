# Проверка прототипа

[English](../../VALIDATION.md) | [简体中文](../zh-CN/VALIDATION.md) | Русский

Реализация является прототипом для разработки. Синтетические проверки и испытания на оборудовании ниже не подтверждают полный охват Synapse или совместимость со всеми моделями.

<a id="completed-locally"></a>
## Выполнено локально

- Нативные перехватчики проверены на собственных синтетических функциях и собственной DLL.
- Сохранены исходные возвращаемые значения и входящее/исходящее состояние ошибок Windows.
- Проверены подавление дублей вложенных вызовов, исключение посторонних дескрипторов/IOCTL, ограниченные очереди, слишком большие буферы, пробелы незавершённых операций и остановка.
- Раздельные отметки входа и возврата API проверены на синтетических вызовах с задержкой.
- Управляемые тесты проверили парсер сборщика, конфиденциальность данных, границы, частичный экспорт, атомарный вывод ZIP и обработку исходного состояния, изменения и восстановления в руководстве.
- Идентичность устройств Windows и HID-дескрипторы экспортированы только чтением.
- Превью WPF без подключения отрисованы настоящими элементами управления.
- Подготовлены синтетические данные семейства Blade, неизвестных PID/usage/структур и незнакомых отчётов; это проверки политики, а не физических моделей.

Собственный нативный стенд пропускает всплеск из 128 завершённых ответов через реальное общее чтение 32 слотов при остановке без дополнительных потерь. - Экспорт фиксирует сеанс, готовит черновики и JSON вне потока вызывающей стороны и повторно использует интервалы действий между черновиками. Детерминированный стенд с блокировкой работы проверяет возврат вызывающей стороны, пока подготовка ещё продолжается; другой проверяет, что отмена не оставляет целевой ZIP.

## Исправления срока записи и потерь копирования, 2026-10-14

Завершённая проверка Claude Opus high диапазона `d904655...f6275b6` дала три подтверждённых проблемы выполнения и одну более узкую проблему диагностики отчёта. Версия 0.2.4 исправляет эти четыре замечания. Новая запрошенная проверка выполняется по закоммиченным исправлениям; её результат отдельно указан с точной ревизией в описании PR.

Собственные регрессии подтверждают, что записи с потерей пяти, затем трёх событий дают восемь пробелов сеанса, сохраняют обе отметки потерь и прежние доказательства, а второе изменённое действие помечают CaptureFailed. Каждая запись получает новую базу нативного счётчика, а накопленные доказательства остаются целыми. Ручной и самостоятельный нативный сбой добавляют по одному пробелу; остановка после самостоятельного сбоя не считает его повторно, новая запись может учесть свой сбой. Сбой опроса на этапах изменения и восстановления сохраняет точное исходное значение в статусе и инструкциях, убирает устаревшую подсказку изменения/отметки и оставляет Mark («Отметить») отключённой до остановки записи. Код CapturePayloadLoss отчёта о качестве определяет unreadable-buffer и buffer-exceeds-limit, не смешивая их со сбоем API, неопределённостью возвращённой длины, ожидающим завершением или скрытием только ради конфиденциальности. ZIP-регрессия проверяет экспорт кода.

## Остаётся перед публичным выпуском

- Типизированные данные ответов на изменения настроек: наблюдаемые тела ответов остаются только метаданными в рамках проверенной грамматики конфиденциальности.
- Испытания участников на других моделях Blade и с другими транспортами.
- Поведение защитного ПО с планируемой подписанной сборкой выпуска.
- Завершение ожидающего асинхронного I/O остаётся вне охвата наблюдателя.

Не заявляются установка драйвера, испытание сна/возобновления, проверка записи в прошивку или публичный выпуск. Здесь записываются пассивные вызовы пользовательского режима, а не контрольное чтение прошивки.

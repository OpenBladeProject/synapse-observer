# Содержимое ZIP с собранными данными

[English](../capture-contents.md) | [简体中文](../zh-CN/capture-contents.md) | Русский

При сохранении создаётся один локальный ZIP. Автоматической загрузки нет. Внутри находятся JSON-черновики ограниченного размера и краткое текстовое руководство.

<a id="manifestjson"></a>
## `manifest.json`

Манифест — запись без конфиденциальных данных сеанса. Он содержит сведения о сборке приложения, идентификационные сведения Windows и инвентаризацию для поддержки, метки HID в пределах сеанса, происхождение подписанных драйверов и модулей Synapse, отметки действий, доказательства проверок специальных клавиш по подсказке, наблюдения feature-вызовов, охват пунктов руководства и число отклонённых записей.

Наблюдения управляющих операций сохраняют API, направление, время, статус завершения, сеансовую метку выбранного интерфейса, структуру отчёта и решение по конфиденциальности. Сохранять тела разрешено только для отчётов, соответствующих проверенной числовой грамматике. Незнакомые, некорректные, неуспешные, чувствительные и превышающие лимит тела скрываются. HMAC-токен для сравнения в пределах сеанса и ограниченные диапазоны изменившихся байтов могут показать совпадение или различие двух непрозрачных отчётов, не создавая постоянного идентификатора устройства.

<a id="coverage-draftjson"></a>
## `coverage-draft.json`

Файл перечисляет каждый конечный элемент шаблона покрытия устройств OpenBlade схемы 2 и текущие требования продукта, ещё не представленные в старом шаблоне. Он также сохраняет общие элементы внешнего питания и ввода по подсказке, когда Windows не может определить класс круглого разъёма/USB-C или функцию физической клавиши в продукте. Каждый элемент имеет статус `NotInvestigated` или `Captured` со ссылками на подтверждающую инвентаризацию Windows, feature-вызов или наблюдение клавиши по подсказке. `Captured` указывает на доказательства для рассмотрения. Он не означает, что записан весь диапазон или пройдены проверки запроса, изменения, восстановления, жизненного цикла либо допуска в продукт. Подтверждение изменения, прочитанное через GET_FEATURE, не подтверждает охват запроса значения: от ответа на запрос его отличает идентичность команды. Для узко определённого проверенного неполного подтверждения температурного режима черновик может сохранить закрытые семантические поля и уникальную ссылку на предшествующий запрос изменения, тогда как непрозрачный начальный байт и тело отчёта остаются исключёнными. Это по-прежнему не подтверждает охват запроса значения или контрольного чтения прошивки.

<a id="annotation-draftjson"></a>
## `annotation-draft.json`

Файл объединяет отметки действий и наблюдения в ограниченные интервалы действий. В черновике v2 есть поле `unchangedReportedValues`; заведомо одинаковые выбранные значения не образуют полную последовательность изменения настройки. Проверяйте `schemaVersion` каждого черновика по [правилам формата](evidence-format.md#derived-draft-schemas-in-028). Сообщения о текущем состоянии, пропуски, определения и намерение провести пробу остаются отдельными `contextMarkers` и не создают интервалы изменения настройки или восстановления. Также сохраняются сводки и наблюдения проверок специальных клавиш. Метки слоя наблюдения: `UserModeFeatureApi`, `WindowsRawInput` и `WindowsInventory`.

Файл помогает сопровождающему найти нужные доказательства. Он не является записью USB-трафика, готовой аннотацией репозитория записей или доказательством принятия запроса прошивкой.

<a id="quality-receiptjson"></a>
## `quality-receipt.json`

Отчёт о качестве подсчитывает записанные и неисследованные элементы покрытия, пробелы инвентаризации, полные интервалы действий, проверенные отчёты, скрытые тела, несвязанные наблюдения, наблюдения специальных клавиш и отклонённые записи. Он различает `ObservedApiFailure`, `CompletionNotObserved` и информационное ограничение `ReturnedLengthNotProvided`. `CapturePayloadLoss` обозначает потерю при копировании в нативном слое из-за нечитаемого буфера или ограничения размера, в том числе при успешном API; она отделена от намеренного скрытия ради конфиденциальности. Наблюдаемый сбой API не равнозначен потере данных сборщиком. Отчёт явно называет частичные, пропущенные, недоступные, неуспешные, отменённые, скрытые и незавершённые результаты. Он также перечисляет оставшиеся этапы для сопровождающего и устанавливает в false утверждения о проверке запроса, проверке изменения и допуске в продукт.

В v2 поля `UnchangedReportedValues` и `IncompleteActionMarkers` описывают заявленную последовательность. `NoMatchingObservation` независимо отмечает интервал без feature-вызовов, поэтому для пустой последовательности с одинаковыми значениями сохраняются оба факта.

<a id="readmetxt"></a>
## `README.txt`

Текстовый файл объясняет те же границы доверия рядом с доказательствами. Сохраняйте его вместе с JSON-файлами при отправке ZIP в запрос поддержки.

<a id="collection-limits"></a>
## Ограничения сбора

- Запись длится не более десяти минут.
- При наблюдении за работающим Synapse один идентифицированный физический ноутбук Blade может предоставить до восьми feature-коллекций.
- Feature-отчёты ограничены 4 096 байтами на наблюдение, 4 MiB сохранённых тел на сеанс, 4 096 наблюдениями и 16 KiB на событие нативного наблюдателя.
- Сеанс принимает до 512 отметок и 128 пунктов пошагового покрытия. При достижении лимита отметок прежние доказательства сохраняются, отклонённые отметки подсчитываются, остановка и экспорт остаются доступны. Независимый черновик покрытия по-прежнему содержит весь сопровождаемый набор возможностей; лимит пунктов руководства его не ограничивает.
- Доказательства специальных клавиш ограничены 256 наблюдениями, 32 наблюдениями на пробу по подсказке и 64 сводками проб.
- Отображаемый текст ограничен 256 символами, непрозрачные токены идентификаторов — 80 символами.
- Сравнение данных сохраняет не более 64 потоков и 16 диапазонов изменившихся байтов на сравнение. Случайный ключ HMAC уничтожается вместе с сеансом и никогда не экспортируется.
- Инвентаризация принимает до 256 HID-интерфейсов, 32 процессов Synapse и 256 модулей на процесс. Инвентаризация для поддержки принимает 32 HID-дескриптора, 24 драйвера устройств, по 8 файлов и 16 фильтров на драйвер, 64 исполняемых модуля, 8 графических адаптеров, 16 дисплеев по 512 режимов, 16 записей яркости по 101 уровню, 16 термальных зон, 8 процессоров и 32 явно отмеченных пробела в данных. Допускается 16 LampArray, каждый с 4 096 лампами, 256 сопоставлениями клавиш и 512 индексами ламп на клавишу. Сводки возможностей HID ограничены 128 структурами на интерфейс; списки цветовых профилей сохраняют до 32 сопоставлений и две записи профилей по умолчанию для каждой запрошенной области. Хешируются только файлы с распознанными стандартными именами; размер каждого файла при хешировании ограничен 16 MiB.
- Каждый JSON-файл ограничен 16 MiB. Экспорт записывает закрытый временный файл, принудительно записывает его на диск и заменяет выбранный ZIP только после успешной записи всех файлов.

ZIP не содержит путей HID-интерфейсов, путей экземпляров PnP, полей серийных номеров, имён пользователей, идентификаторов процессов, командных строк, данных учётных записей, путей модулей и произвольной памяти процессов. О дальнейшей работе см. [требования к доказательствам для поддержки](support-evidence-requirements.md).

Числовые диапазоны не являются правилами допуска в продукт в этом сборщике. Внутри точно проверенных семейств управления температурным режимом, Custom CPU/GPU, фиксированной скоростью вентилятора и пределом заряда незнакомые числовые значения сохраняются с `numericMeaningUninterpreted: true`. Проверки семейства отчёта, тега управления, канала, длины, контрольной суммы, заполнения, источника и статуса продолжают действовать. Входные аргументы запроса должны соответствовать проверенной структуре с нулевыми значениями. Это позволяет исследовать значения новых моделей, не заявляя об их понимании или поддержке.

Режимы клавиатуры фиксируются для внутреннего анализа. Участников не просят определять режим Normal или Driver. Feature-отчёты режима остаются в пассивном наблюдении; проверки клавиш по подсказке используют контекст режима Unknown, не угадывая его по клавишам.

Данные о цветовых профилях включают сопоставления Windows и профили SDR/HDR по умолчанию. Они не включают содержимое профилей и не подтверждают точность калибровки или цветового охвата. Сборщик пока не перечисляет отдельную топологию управляющего и виртуального интерфейсов, необходимую для незнакомого стека нативного драйвера яркости. Проверка подписи файлов драйвера не проверяет отдельно подпись каталога: результат `Unsigned` не доказывает отсутствие у драйвера Windows действительной подписи каталога. Эти ограничения сбора включены в отчёт о качестве.
